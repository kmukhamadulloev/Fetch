# HTTP API

The API is same-origin under `/api`; the machine-readable contract is
`docs/openapi.yaml`. All normal errors use a non-2xx status and this shape:

```json
{"error":{"code":"RUNTIME_MISSING","message":"A required runtime component is missing: yt-dlp","details":null}}
```

Internal stack traces and internal error text are not returned. Process details
are retained in Logs where available.

## Status and analysis

- `GET /api/status` returns application version and real storage/runtime
  readiness.
- `POST /api/media/analyze` with `{"url":"https://..."}` delegates the URL to
  yt-dlp and returns normalized media or playlist metadata, entries, and
  formats.

## Downloads and history

- `GET|POST /api/downloads`
- `GET|DELETE /api/downloads/{job_id}`
- `POST /api/downloads/{job_id}/stop`
- `POST /api/downloads/{job_id}/resume`
- `POST /api/downloads/{job_id}/retry`
- `GET /api/history`

A create request contains `url`, `mode` (`video` or `audio`), and optional
`title`, `format_id`, `quality`, `container`, `video_codec`, `audio_codec`,
nullable analyzed `duration_seconds`, metadata/thumbnail/subtitle booleans, and
`output_directory`. Responses include persistent state, nullable
byte/progress/speed/ETA fields, typed failure fields, and timestamps. Deleting a
job removes metadata only; it never silently deletes media.

Playlist entries are queued as individual jobs with a shared `playlist`
context containing its ID, title, and one-based item index. Each item keeps its
own persisted progress and actions while the server safely places it under
`Playlists/<title> [<playlist-id>]/` with an ordered filename.

## Completed files

- `GET /api/completed`
- `GET /api/files/{opaque_file_id}/download`
- `GET /api/files/{opaque_file_id}/stream`
- `GET /api/files/{opaque_file_id}/thumbnail`
- `POST /api/files/{opaque_file_id}/reveal` (host device only)
- `DELETE /api/files/{opaque_file_id}`
- `PUT|DELETE /api/files/{opaque_file_id}/progress`

File paths are never serialized and cannot be supplied to an endpoint. The
stream route supports a single bounded, open-ended, or suffix `Range`, returns
`206` and `Content-Range`, and returns `416` for invalid ranges. Neither route
transcodes.

Completed responses expose nullable `playlist` context with its ID, title, and
one-based item index, plus `thumbnail_available`; they never expose a filesystem
or cache path. Playlist context is derived from the completed file's persisted
download job, so older databases remain compatible. The thumbnail route serves
immutable JPEG artwork generated by yt-dlp and managed FFmpeg from the
application-data cache.

The progress PUT body contains finite non-negative `position_seconds` and a
positive `duration_seconds`. Fetch marks the final five percent completed and
returns the persisted playback record. DELETE resets progress. Progress belongs
to the local Fetch library rather than an account, so every allowed LAN client
shares it. File deletion cascades to its playback record.

Reveal resolves the persisted path and opens its containing folder through the
host operating system; non-host clients receive `LOCAL_CLIENT_REQUIRED` with
`403`. Delete permanently removes the media and cached artwork, then removes
the completed-file record while retaining the associated job history.

## Settings and network

- `GET|PUT /api/settings`
- `GET /api/network`
- `GET|PUT /api/proxy` (host device only)

Settings include bind IP, port, allowed CIDRs, output directory, concurrency,
browser-open preference, per-user system-start preference, and yt-dlp
auto-update preference. Invalid IP, port, CIDR, concurrency, directory,
startup-registration, and unavailable listener values return
`INVALID_SETTINGS`. CIDRs, new-job download defaults, concurrency, and listener
changes apply immediately. A successful listener change returns
`listener_changed: true` so the browser can replace its location with the new
address. Network info advertises only addresses compatible with the active bind
and allow-list, reports whether the requesting browser is on the Fetch host via
`local_client`, and explicitly reports that authentication is disabled. The UI
uses these URLs to generate local QR codes; no external QR service is contacted.
Only a host client may change `start_with_system`; remote allowed clients receive
`LOCAL_CLIENT_REQUIRED`. Enabled registration launches the executable with
`--background` and does not force-open a browser.

Proxy settings are intentionally separate from the LAN-readable application
settings response. The typed body is `{"mode":"system|direct|custom","url":null|string}`.
System and direct modes require a null URL. Custom mode accepts only a validated
unauthenticated HTTP, HTTPS, SOCKS4, or SOCKS5 endpoint. Both proxy operations
require a host client; remote allowed clients receive `LOCAL_CLIENT_REQUIRED`.
Saving hot-applies to analysis and queued/new yt-dlp processes without
interrupting an active download.

## Runtime and diagnostics

- `GET /api/runtime`
- `POST /api/runtime/{yt-dlp|ffmpeg|ffprobe}/{install|update|repair}` returns
  `202` after the operation is scheduled.
- `GET|DELETE /api/logs`
- `GET /api/diagnostics`

FFmpeg and FFprobe actions operate on the managed pair.

## Events

`GET /api/events` is an SSE stream with keepalives. Event names are:

- `download.created`, `download.progress`, `download.postprocessing`,
  `download.completed`, `download.failed`, `download.stopped`
- `library.completed`, `library.progress`, `library.progress-cleared`
- `runtime.missing`, `runtime.installing`, `runtime.updating`, `runtime.ready`,
  `runtime.failed`

Download event data is the current job, `library.completed` data is the newly
persisted completed file, progress events carry the saved record or cleared file
ID, and runtime event data is the current component.
Unknown `/api/*` paths always return typed JSON 404 responses and are never
handled by the SPA fallback.
